# A 股个股财务体检

## 数据边界（先读这一条）

**本技能不提供、不抓取、不转发任何行情或财务数据。**

它只做三件事：**校验、计算、出成品**。数据由调用方（用户的智能体或用户本人）
通过其自有数据源取得后，按下方契约传入。

这么设计有两个原因：

1. **资质边界。** 平台「股票信息服务平台」类目要求增值电信业务经营许可证
   + 深交所《专有信息经营许可合同》+ 上交所《证券信息经营许可合同》。
   技能若自行抓取证券数据并交付给用户，等于以个人身份从事需要许可的
   证券信息服务——不只是过不了审，是本来就不该做。
2. **职责分离。** 取数已有专门技能承担（如 `tushare-data`、`common` 数据网关，
   凭据存在**用户自己**的 `secrets.env` 里）。把取数与算数混在一个包里，
   等于用我们的名义替用户向第三方取数。

包内所有脚本**零网络依赖**，只用 Python 标准库，可离线审计：

```bash
python -X utf8 -m unittest discover -s tests -p "test_*.py" -k NoNetworkCapability
# 4 项全绿：无网络导入 / 无数据源域名 / 无内置数据样本 / 报告披露来源
```

判据是对**剥离注释与文档串后的真实代码行**做匹配——
注释里写着"本技能不用 tushare"是合法的，直接 grep 会误报。
所以别用下面这条粗筛当验收（它会命中注释，属于预期）：

```bash
grep -rEi "urllib|requests|socket|httpx|aiohttp|tushare|akshare" scripts/*.py
```

`tests/test_checkup.py::TestNoNetworkCapability` 把这条边界钉成了构建门禁——
任何一次「顺手加个取数」都会让测试变红（变异测试 M17/M18 双向验证过）。

## 数据从哪来

由**调用方**决定，本技能不指定也不推荐任何数据源。常见做法：

- 用户的智能体调用其已配置的数据技能（Tushare / 问财等），把结果转成本技能的 JSON 契约；
- 用户自己从披露文件、Excel 或数据库导出后整理成 JSON；
- 用户手工整理。

`source` 字段必填，报告会**原样印出**这句话，用于声明数据由谁提供。

## 执行方式

> ⚠️ **先确认解释器**。很多环境（含 WorkBuddy 宿主）**只有 `python` 或 `py`，没有 `python3`**。
> 直接敲 `python3 checkup.py` 会得到 `command not found`。
> 下面的命令统一写成 `$PY`，先探测一次即可，后续照抄。

```bash
cd <本技能包根>/scripts

# 探测一次：python3 → python → py，取第一个可用的 3.8+
# 先置空：若调用方环境开了 `set -u`，未赋值的 $PY 会直接报 unbound variable，
# 连下面那句「请先安装 Python」都打不出来（实测）。
PY=""
for c in python3 python py; do
  if command -v "$c" >/dev/null 2>&1 \
     && "$c" -c 'import sys;raise SystemExit(0 if sys.version_info>=(3,8) else 1)' 2>/dev/null; then
    PY="$c"; break
  fi
done

# 探测不到就明确报错退出，不要让空 $PY 变成一句 " : command not found"
if [ -z "$PY" ]; then
  echo "未找到 Python 3.8+。本技能只用标准库，装好 Python 3.8 或更高版本后重试。" >&2
  echo "Windows 可用: winget install Python.Python.3.12  或  https://www.python.org/downloads/" >&2
  exit 1
fi
echo "使用解释器: $PY"

# 1. 先看输入格式
"$PY" -X utf8 checkup.py --spec

# 2. 用自己准备的数据出报告
"$PY" -X utf8 checkup.py --data my_data.json
"$PY" -X utf8 checkup.py --data my_data.json --peers my_peers.json
```

> `-X utf8` **不是可选项**。Windows 中文控制台按 cp936 输出，管道里读回来是乱码；
> 没有 `PYTHONUTF8` 兜底时必须显式加。
>
> 包里**没有**第三方依赖，只用 Python 标准库，所以只要 3.8+ 就能跑，不需要 `pip install`。

**不要自己写分析脚本**——勾稽、红旗、杜邦、分位、渲染都已实现。

| 参数 | 说明 |
|---|---|
| `--data FILE` | 标的财务数据 JSON（必填，格式见 `--spec`） |
| `--peers FILE` | 同业样本 JSON（可选，少于 3 家不给分位） |
| `--out DIR` | 报告输出目录（默认 `../reports`） |
| `--json` | 只输出 JSON，不渲染 HTML |
| `--spec` | 打印输入契约后退出 |

输出：

```
<out>/600519_SH_20260930.json   完整结构化指标
<out>/600519_SH_20260930.html   单文件自包含报告（内联 SVG，无外链）
```

## 输入契约（摘要）

完整版跑 `python3 checkup.py --spec`。

```json
{
  "code": "600519.SH",  "name": "贵州茅台",  "industry": "白酒",
  "source": "Tushare Pro（用户自有凭据）",
  "unit": "yuan",
  "income":   [ { "report_date": "2026-09-30", "revenue": 1.2e11, "net_profit": 6e10 } ],
  "balance":  [ { "report_date": "2026-09-30", "total_assets": 3e11,
                  "total_liab": 6e10, "total_equity": 2.4e11 } ],
  "cashflow": [ { "report_date": "2026-09-30", "cfo": 5e10 } ]
}
```

字段名**中英文、大小写、常见数据源写法都认**（见 `ingest.FIELD_SPEC`），
比如 `total_revenue` / `TOTAL_OPERATE_INCOME` / `营业总收入` 等价。

三条硬性要求：

1. `source` 必填——没有来源说明的报告无法自证数据由调用方提供。
2. 三张表缺一不可——缺表的「财务体检」会给出看似完整、实则失真的结论。
3. **建议 8 期以上**（含去年同期），否则同比无法计算。

## 三条必须知道的口径

### 1. 定期报告是年初至今累计（YTD）

Q3 的营收是 1-9 月累计，不是第三季度单季。
所以**趋势比较一律用同比（同期对同期）**，不能拿 Q3 累计和 Q2 累计直接比。

脚本自动找去年同期。**找不到去年同期时不会拿上一期硬算**：
增速留空，`comparison_basis` 标为「缺失」，报告页顶部给出黄色警告。
（把环比当同比是这类产品最常见的错误，且用户看不出来。）

### 2. 金融业（银行/保险/证券）不适用工商企业指标

银行没有"营业成本/毛利率"概念，总资产周转率天然是 0.01 量级（正常现象）。
脚本按 `industry` 字段识别并跳过这些指标，并在报告中说明原因。
若你的数据把银行归在别的行业名下，请如实填写 `industry`。

### 3. 同业样本少于 3 家不给分位

百分位在 2 个样本上没有统计意义。少于 3 家时明确说明原因，不硬给一个分数。

「**没提供**同业样本」和「**提供了但太少**」是两件事，报告里措辞不同：
前者说"未提供，本节无内容"，后者说"仅 N 家，不足以下横截面结论"。
两种情形都**不出空表**——只有表头的表会被读成"每个指标都缺失"。

## 同业对比为什么给「分位带」而不只给中位数

一个中位数只能回答"我比中位高还是低"，回答不了另外两个更要紧的问题：
**这个分布本身有多宽**、**我离中位有多远**。

所以每项指标除中位数外，还给出 **p10 / p25 / p50 / p75 / p90 分位带**
（口径与 `valuation-model` 的 PE-Band 一致，线性插值分位数），
渲染成分布条：浅带 p10–p90、深带 p25–p75、竖线中位、圆点本公司位置。

读法：

- **深带窄** → 行业普遍如此。此时偏离中位更有信息量，说明是个体特征；
- **深带宽** → 行业本身参差不齐。偏离中位不一定是本公司的问题，可能只是常态分布；
- **本公司圆点变红** → 已落在 p10–p90 之外（贴边显示），是行业里的极端值。

这一步的必要性有实测支撑：本项目曾用绝对阈值打分，
把资产负债率 70% 的比亚迪打到 19.1 分（汽车行业 70% 是常态）。
只有相对位置、没有分布宽度，同样会重犯这类错误。

## 为什么必须有同业对比

绝对阈值评分一定会误判。本项目第一版用绝对阈值打分（ROE≥20 满分、
负债率越低越好……），实测结果：

| 公司 | 绝对分 | 问题 |
|---|---|---|
| 比亚迪 | **19.1** | 汽车行业 70% 负债率是常态，被判"不及格" |
| 诺思兰德 | **51.65** | 净利 -4590 万、ROE -16.5%，却比比亚迪分高 |

根因：亏损时大量比率为 None 被跳过，剩下的毛利率/扣非占比反而拿高分。

**修法：删除绝对分，只保留同业横截面百分位。** 改后：
茅台 87.2 · 恒瑞 76.0 · 长江电力 74.1 · 比亚迪 68.2 · 工行 50.4 · 诺思兰德 29.1。

排序符合常识。宁可只给相对位置，也不给会误导的绝对分。

## 开发时踩过的坑（都是真实缺陷，已加回归测试）

| 缺陷 | 症状 | 修法 |
|---|---|---|
| **绝对阈值评分** | 比亚迪被评 19.1 分；亏损公司却拿 51.65 分，方向完全反了 | 删除绝对分，只保留同业百分位 |
| **亏损零红旗** | 归母 -4590 万，红旗 0 条——比率规则在亏损时全被跳过 | 增加「净利为负」「扣非为负」「CFO 为负」三条独立规则 |
| **小基数误报** | 茅台应收同比 +1327% 被报高危，实际仅占总资产 0.11% | 报高危前先看绝对占比（≥5% 或占营收 ≥5%） |
| **银行崩溃** | 毛利率为 None 导致格式化抛异常 | 识别行业，金融业不算毛利率 |
| **勾稽口径混淆** | 「经营现金流 vs 净利润」被写成"差异率 143%"，像报表对不上 | 改称「现金流富余率」并加说明 |
| **过度转义** | `<b>金融业</b>` 被 escape，页面上直接显示标签字面文字 | 受控串不 escape，并用变异测试钉住 |
| **空白同业表** | 2 家样本时渲染出「只有表头、0 行数据」的表，读者读成"每项都缺失" | 无逐指标结果时不出表，改出一句说明 |
| **分位带插值退化** | 分位测试样本点恰好落在整数索引上，不插值的退化实现也全绿 | 补两点/非整数位置用例，变异测试 M23 钉住 |

## 已知限制

- **数准确性由调用方负责**：本技能只保证计算方法正确，不校验输入数据本身的真伪。
- **不做估值**：只做财务体检，不含 PE/PS 等估值分位。
- **不做预测**：所有指标基于已提供的定期报告数据，无任何前瞻性判断。
- **不做代码校验**：股票代码由调用方填写，本技能不校验其是否真实存在。
