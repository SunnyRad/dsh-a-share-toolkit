# A 股估值分位体检

## 这个技能解决什么问题

普通 LLM 回答"估值贵不贵"，要么编一个 PE 数字，要么算出一个方向相反的结论。
你把估值序列交给它，它做三件普通实现**经常做错**的事：

1. **历史分位**：当前 PE/PB/PS 在自身历史中处于什么位置。
2. **陷阱识别**：判断当前分位结论是否可信，不可信就明说不可信。
3. **指标选择**：告诉你这种情况下**该看哪个指标**（而不是永远报 PE）。

## ⚠️ 本技能不提供数据

**数据由调用方自带**，本技能不抓取、不转发、不缓存任何行情或估值数据。
包内所有脚本零网络依赖，只用 Python 标准库，可离线审计：

```bash
python -X utf8 -m unittest discover -s tests -p "test_*.py" -k TestCapabilityOnly
# 6 项全绿：无网络导入 / 无数据源域名 / 取数模块已删除 /
#          契约层无价格字段 / 报告披露来源 / SKILL.md 声明不提供数据
```

判据是对**剥离注释与文档串后的真实代码行**做匹配——
注释里写着"本技能不用 tushare"是合法的，直接 grep 会误报。
所以别用下面这条粗筛当验收（**它会命中那行注释，属于预期**）：

```bash
grep -Ei "urllib|requests|socket|http|tushare|akshare" scripts/*.py
```

`tests/test_valuation.py::TestCapabilityOnly` 把这条边界钉成了构建门禁——
任何一次「顺手加个取数」都会让测试变红（变异 M23–M27 + M31–M35双向验证过）。
`tools/pack.py` 另有第二道闸：包内出现取数层文件或数据源域名，打包直接失败。

两条原因，都不是口味问题：

1. **合规**。平台「股票信息服务平台」类目要求增值电信业务经营许可证
   + 沪深交易所《证券信息经营许可合同》，个人主体拿不到。技能自行抓取
   证券数据并交付给用户，等于以个人身份从事需要许可的证券信息服务。
2. **边界**。取数已有专门技能承担（`tushare-data` / `common` 数据网关，
   凭据存在**用户自己**的 `secrets.env`）。本技能只负责「算对、校验、出成品」。

> v0.1 曾直接从东财 datacenter 接口取数，v0.2 已整体删除该层
> （原 `valuation.py` 取数模块不复存在），并由四条测试 + 三条变异锁死：
> 把取数加回来、硬编码数据源域名、报告不再披露数据来源，构建都会变红。

## 为什么"历史分位"这么容易算错

这是本技能存在的核心理由。四个坑，每一个都会给出**方向相反的结论**：

### 坑 1：亏损股 PE 为负，朴素算法判成"历史极低位"

实测隆基绿能 601012：当前 PE_TTM = **-11.78**（公司在亏损）。

```
朴素做法：把 -11.78 和历史序列一起排序
结果：  22.9% 分位 → 报告会写「处于历史极低位、极度低估」
真相：  公司亏损，PE 这个指标此刻没有意义
```

本技能的处理：负 PE 一律判为「不适用」，不出分位，并引导改用 PB。

### 坑 2：全史亏损，任何分位都是噪声

实测诺思兰德 920047：全史 1444 个交易日 PE **全为负**。
朴素算法给出 72.4% 分位——一个纯粹由噪声生成的数字。

### 坑 3：新股历史太短，分位没有统计意义

实测 301601 只有 438 个交易日（约 1.7 年）。
本技能设两级门槛：少于 250 个交易日不出分位；少于 750 个标注「仅供参考」。

### 坑 4：周期股只看 PE 会得出反向结论

实测海螺水泥 600585：

| 指标 | 当前值 | 历史分位 |
|---|---:|---:|
| PE(TTM) | 21.81 | **100.0%** |
| PB(MRQ) | 0.52 | **4.7%** |

只看 PE 会说「史上最贵」，但净资产角度股价其实处于**历史最便宜**的位置。
这是周期股在盈利顶部的典型形态：利润高 → PE 分母大 → PE 反而显得便宜/贵的逻辑反转。

本技能检测到 PE 与 PB 分位差超过 40 个百分点时，判定为**周期特征**，
并自动把主判断指标切到 PB。

> 上游成熟项目（`valuation-model` 技能的 PE-Band 脚本）在文档里写了
> 「周期股用 PB，避免用 PE」，但脚本只输出 PE 分位、从不做这个判断。
> 本技能把这个判断真正落地了。

## 执行方式

> ⚠️ **先确认解释器**。很多环境（含 WorkBuddy 宿主）**只有 `python` 或 `py`，没有 `python3`**。
> 直接敲 `python3 checkup.py` 会得到 `command not found`。
> 下面的命令统一写成 `$PY`，先探测一次即可，后续照抄。

```bash
cd <本技能包根>/scripts

# 探测一次：python3 → python → py，取第一个可用的 3.8+
# 先置空：若调用方环境开了 `set -u`，未赋值的 $PY 会直接报 unbound variable，
# 连下面那句「请先安装 Python」都打不出来（实测）。
PY=""
for c in python3 python py; do
  if command -v "$c" >/dev/null 2>&1 \
     && "$c" -c 'import sys;raise SystemExit(0 if sys.version_info>=(3,8) else 1)' 2>/dev/null; then
    PY="$c"; break
  fi
done

# 探测不到就明确报错退出，不要让空 $PY 变成一句 " : command not found"
if [ -z "$PY" ]; then
  echo "未找到 Python 3.8+。本技能只用标准库，装好 Python 3.8 或更高版本后重试。" >&2
  echo "Windows 可用: winget install Python.Python.3.12  或  https://www.python.org/downloads/" >&2
  exit 1
fi
echo "使用解释器: $PY"

# 1. 先看输入格式
"$PY" -X utf8 checkup.py --spec

# 2. 用自己准备的数据出报告
"$PY" -X utf8 checkup.py --data my_valuation.csv
"$PY" -X utf8 checkup.py --data my_data.json
```

> `-X utf8` **不是可选项**。Windows 中文控制台按 cp936 输出，管道里读回来是乱码；
> 没有 `PYTHONUTF8` 兜底时必须显式加，否则你看到的是 `M-1M->M-<M-<...` 而不是中文。

**不要自己写数据分析脚本**——契约校验、分位计算、陷阱识别、报告渲染都已实现。

参数：

| 参数 | 说明 |
|---|---|
| `--data FILE` | 估值数据，`.csv` 或 `.json`（格式见 `--spec`） |
| `--out DIR` | 报告输出目录（默认 `../reports`） |
| `--json` | 只输出 JSON，不渲染 HTML |
| `--spec` | 打印输入格式说明后退出 |

输出：

```
<out>/600519_SH_20261109.json   完整结构化指标
<out>/600519_SH_20261109.html   单文件自包含报告（内联 SVG，无外链）
```

## 输入格式

### 数据从哪来（先读这一条）

本技能不取数。你手上那份数据怎么变成下面的格式，是最容易卡住的一步，
所以这里给三条现成路径——**第三条不用你手写任何东西**。

**路径 1：已经有 Tushare 导出（最省事）**

Tushare 的 `daily_basic` 接口导出后长这样，**直接喂给包里的转换器**即可：

```
ts_code,trade_date,pe_ttm,pb,ps_ttm
600519.SH,20261109,31.43,7.13,9.54
```

```bash
"$PY" -X utf8 to_contract.py --in daily_basic.csv --out my_data.json \
    --code 600519.SH --name 贵州茅台 --industry 白酒 \
    --source "Tushare Pro（自有凭据）"
```

转换器会自动做四件事：`ts_code` 这类多余列忽略、`pb`→`pb_mrq` 别名映射、
`20261109`→`2026-11-09` 日期归一、**乱序行按日期倒序排**。
加 `--dry-run` 可以先看它打算怎么映射，不写文件。

**路径 2：行情软件导出的中文 CSV**

东方财富/同花顺导出的「日期 / 市盈率TTM / 市净率」这类列名，转换器也认
（全角括号、空格、大小写都能匹配）：

```bash
"$PY" -X utf8 to_contract.py --in 导出.csv --out my_data.json --code 600519.SH
```

> ⚠️ 价格、成交量、涨跌幅这类列**不会被读取**，转换器会明确告诉你它忽略了哪几列。
> 本技能只做估值，不做行情。

**路径 3：手写（只适合极小样本）**

按下面的 CSV/JSON 格式自己整理。少于 250 个交易日不会出分位。

### 通道 A：CSV（只要估值历史，最省事）

```csv
date,pe_ttm,pb_mrq,ps_ttm
2026-11-09,20.5,6.1,9.2
2026-11-08,20.1,6.0,9.0
```

### 通道 B：JSON（历史 + 行业横截面 + 元信息）

```json
{
  "code": "600519.SH",
  "name": "贵州茅台",
  "industry": "白酒",
  "source": "Tushare Pro（用户自有凭据）",
  "history": [
    {"date": "2026-11-09", "pe_ttm": 20.5, "pb_mrq": 6.1, "ps_ttm": 9.2}
  ],
  "industry_rows": [
    {"code": "000858.SZ", "name": "五粮液", "pe_ttm": 18.0, "pb_mrq": 4.2}
  ]
}
```

### 契约的容忍度（为了一次就能喂对）

| 方面 | 接受什么 |
|---|---|
| 日期 | `2026-11-09` / `2026/11/09` / `20261109` / `2026-11-09 00:00:00` |
| 列名 | 中英文、大小写都认：`pe_ttm` / `PE_TTM` / `市盈率` / `滚动市盈率` |
| 数字 | `"1,234.56"` / 全角 `１２３` / `"20.5倍"` |
| 空值 | `null` / 空串 / `-` / `—` / `N/A` / `无数据` 一律视为缺失 |
| 行序 | 随意。本技能自己按日期倒序排，**不依赖你的行序** |
| 亏损 | 负 PE **照原样抄**，不要改成 0 或删掉——负号是判断「PE 失效」的唯一依据 |

### 会被拒绝的输入（报错而不是猜）

| 情形 | 为什么拒绝 |
|---|---|
| 缺 `source` | 报告无法自证数据由谁提供，合规上不成立 |
| 行缺日期 | 分位每一步都按日期排序 |
| `history` 为空 | 单点数值回答不了「处于历史什么位置」 |
| **三列正值样本全为 0** | 没有可比较基准。错误信息会告诉你需要 250 个交易日 |
| 最新一行三列全空 | 当前值缺失时任何分位都是假的 |
| `.xlsx` 等其它格式 | 本技能只认 `.csv` / `.json` |

三列**只需给一列**。只看 PB（亏损股）是合法用法，
本技能逐个指标判断「有数据 / 无数据」，不会因为缺 PE 就拒绝整份数据。

> 拒绝与降级的分界：**只要还有一列有正值，就出报告；一列都没有，就报错。**
> 所以「PE 全为负 + 给了 PB 正值」会正常出报告并自动改用 PB；
> 而「只给 PE 一列且全为负」会被拒绝——那时本工具确实算不出任何分位。

## 产品边界：不做行情

本技能是**估值分析工具**，不是行情工具：

- 不提供实时报价、不画 K 线、不做分时走势
- 报告**不输出股价、不输出市值**，只呈现估值倍数与其历史位置
- 输入契约里**根本没有价格字段**——`close` / `open` / `volume` / `change_pct`
  给了也不会被读取（契约层只输出 `TRADE_DATE` + PE/PB/PS 四个键）

## 数据可信度（本技能的结构性优势）

市面上同类技能大多**自己接数据接口**，于是多了一个「接口返回的数字可信吗」的问题——
有的甚至要在描述里专门声明「内置 AI 幻觉防控模块」。

**本技能不存在这个问题，因为它不产生任何数字。**

| 问题 | 自接数据的工具 | 本技能 |
|---|---|---|
| 数字从哪来 | 第三方接口，用户看不到 | **你给的文件**，报告印出 `source` 原样 |
| 接口改字段/限流 | 会静默变成「无数据」或报错 | 不可能，没有请求 |
| 数字被算错 | 用户无法复核 | 分位 = 排序位置，**你可以拿原始 CSV 手算核对** |
| AI 编造数字 | 需要额外做幻觉防控 | **架构上不可能**，代码只有纯算术 |

具体保障：

1. **`source` 字段必填**，报告会原样印出这句话（如「Tushare Pro（自有凭据）」），
   你随时能追溯每份输入的出处。
2. **包内零网络依赖**，只用 Python 标准库，`tests/` 里有一条
   `TestCapabilityOnly.test_no_network_imports` 强制检查。
3. **报告不出现任何你没给过的数字**——所有分位都可由 `history` 手算复核。
4. **数据错会如实放大**：本技能不做数据校验（除了格式与样本量），
   它无法分辨你抄错了一位小数。这是它的边界，写在这里而不是藏在脚注。

## 三条必须知道的口径

### 1. 分位是纵向比较，跨公司不可比

「PE 处于自身历史 20% 分位」不等于「比同行业便宜」。
同行业横截面是另一张表，两者含义不同，报告里分开呈现。

### 2. 低分位不等于会涨

历史分位只描述「现在的倍数在自身历史里排在哪」。
估值低可以更低，高分位可以更高。报告固定包含这条说明。

### 3. 金融业与周期股的 PE 含义不同

银行 PE 天然低（7-10 倍是常态），煤炭水泥在盈利顶部 PE 也低。
本技能不对这类差异做绝对阈值判断，只用相对位置 + 背离提示。

### 同业横截面：快照含本公司时会自动剔除

最常见也最自然的输入是「某板块某日全部公司估值」，**里面必然有本公司**。
若不剔除，本公司的估值会同时充当「被比价者」和「基准样本」：

```
快照 4 行（含本公司），本公司 PE 21.8，另外 3 家分别 9.0 / 15.0 / 38.0
朴素做法：分位 = 2/4 = 50.0%（把自己也数进分母），标题写「4 家」、排名写「1/5」
正确做法：分位 = 2/3 = 66.7%（同业 3 家），排名「3/4」，页面写明已剔除本公司
```

剔除后报告会显式说明「已从同业样本中剔除本公司」，
避免读者把「同业 N 家」误读成「这个板块只有 N 家公司」。

这不是装饰。开发过程中变异测试真实揪出两条**假绿**测试：

| 变异 | 症状 |
|---|---|
| M12 | 断言检查「不预示未来涨跌」，而变异删的是「低分位不等于会涨」——两句话在同一段里，删掉后仍通过 |
| M14 | CSV 样例本身就是倒序写的，删掉排序逻辑后测试仍通过 |

两条都已改成真正有效的判据（M14 改为喂**乱序**数据）。

## 开发时踩过的坑（都是真实缺陷，已加回归测试）

| 缺陷 | 症状 | 修法 |
|---|---|---|
| **负 PE 污染分位** | 隆基绿能亏损，朴素算法给出 22.9% 分位 → 「历史极低位」 | 只取 >0 的值做基准，负值判为不适用 |
| **字段大小写不匹配** | 数据源给 `PE_TTM`，代码取 `pe_ttm` → 整份报告每个数字都是「无数据」，但页面正常渲染 | 加 `FIELD_MAP` 显式映射，测试钉住 |
| **行业名称被覆盖** | `industry` 键先存字符串后存 dict，标题显示异常 | 拆成 `industry` 与 `industry_comparison` |
| **周期股只看 PE** | 海螺水泥 PE 分位 100% / PB 分位 4.7%，只报 PE 会说「史上最贵」 | 背离超 40 个百分点即判周期特征，主指标切 PB |
| **同业快照误判非法** | 行业横截面不是时间序列，共用 `normalize_rows` 后会因「缺日期」整份报错 | 拆出 `normalize_peer_rows`，同业不要求日期 |

## 合规声明

报告固定包含：

> 本报告为估值数据分析工具输出，不构成任何投资建议，不包含也不应被理解为买卖推荐、目标价或收益预测。历史分位只描述「当前估值倍数在过去若干年中的相对位置」，**不预示未来涨跌**。低分位不等于会涨，高分位不会等于会跌。

正文不出现「建议买入/卖出/目标价/必涨/推荐评级」。

## 已知限制

- **分位质量取决于你给的数据**：数据错，结论就错。本技能不做数据校验
  （除了格式与样本量），它无法分辨你抄错了一位小数。
- **历史深度由你决定**：想让分位覆盖 10 年，就得提供 10 年序列。
- **不做估值模型**：不做 DCF/DDM/SOTP，只做相对估值的历史位置。
- **不做预测**：不预测 PE 会回到什么水平，只陈述当前在历史中的位置。
